## Project

### GRAB | 한정 수량 DROP 커머스 서비스

> 정해진 판매 시각에 한정 수량의 상품을 구매하는 커머스 서비스입니다. 판매 시작 시점에 구매 수요가 집중되는 방식이 특징입니다.
>
> - **기간**: 2026.09.22 ~ 2026.11.04
> - **인원**: 4명
> - **역할**: 회원 인증·인가 전반, 백엔드 초기 환경 구성

**주요 담당 기능**

- **인증·인가**: HttpOnly 쿠키 기반 JWT 인증·인가, CSRF·CORS 및 Redis Lua 기반 Refresh Token 교체·인증 세션 관리
- **이메일·소셜 로그인**: 이메일 인증(HMAC 저장·발송 제한·비동기 발송), 카카오·구글 OIDC 로그인 구현
- **개발·배포 환경 및 API 문서**: Docker Compose 개발 환경과 GHCR 이미지 배포 워크플로우 구성, 인증 API 명세 작성·관리

**문제 해결 경험**

- **인증 조회 처리량 약 1.95배 개선**: 토큰의 회원 식별자를 DB 내부 ID로 변환하는 조회가 인증 요청마다 반복됐습니다. 해당 매핑을 Caffeine으로 캐싱하고 조회 트랜잭션을 조정했습니다. 로컬 부하 테스트(DB 왕복 지연 약 3ms, 가상 사용자 1,600명)에서 내 정보 조회 처리량을 초당 약 760건에서 약 1,500건으로 높였습니다.
- **동시 로그인 시 메모리 부족 대응**: 로컬 동시 로그인 부하 테스트에서 서버가 메모리 부족(OOM)으로 응답하지 않는 문제를 재현했습니다. GC 로그 분석으로 비밀번호 해시(Argon2)의 동시 실행이 원인임을 파악해 실행을 4건으로 제한하고, 대기 시간 초과 시 재시도를 안내하도록 했습니다. CPU 2개·메모리 1GiB 환경에서 가상 사용자 80명의 일제 로그인 테스트를 2회 수행해, 각 회차 80건 모두 성공하고 OOM·응답 불가가 없음을 확인했습니다.

### 마주한끼 | 실시간 1:1 식사 매칭 서비스

> 지역·시간·식사 취향·대화 성향을 바탕으로 함께 식사할 상대를 연결하는 서비스입니다. 조건에 맞는 상대를 제안하고, 양쪽이 수락하면 매칭과 채팅방이 생성됩니다.
>
> - **기간**: 2026.08.21 ~ 2026.09.03
> - **인원**: 2명
> - **역할**: 실시간 매칭 전 과정, 인증·보안 기반, 성향 설문·후기, 초기 환경 구성

**주요 담당 기능**

- **실시간 매칭** 요청·취소, 성향 점수 기반 후보 제안·수락·거절·확정 구현
- **대기 상태 관리**: Valkey에 대기 정보를 저장하고, PostgreSQL 기록을 기준으로 누락 정보 복구·요청 만료 처리 구현
- **성향 설문·후기 작성**과 후기 기반 점수인 다시한끼 지수 계산 구현

**문제 예방 설계 및 검증**

- **동시 수락·취소·만료 시 중복 매칭 예방**: 수락과 취소·만료가 겹치면 취소되거나 만료된 제안이 확정되거나 매칭이 중복 생성될 수 있습니다. 비관적 락으로 제안과 매칭 요청을 일정한 순서로 잠그고, 매칭·참여자 정보·채팅방 생성을 한 트랜잭션으로 묶었습니다. 로컬 PostgreSQL에서 양쪽 동시 수락, 수락과 취소의 경합 등 6종을 각 100회 검증해, 총 600회에서 중복 매칭·상태 불일치·데드락·타임아웃 0건을 확인했습니다.
- **대기 정보 유실 시 DB 기준 복구**: 매칭 요청은 PostgreSQL에, 대기 정보는 Valkey에 저장하므로 두 저장소의 상태가 어긋날 수 있습니다. Valkey의 대기 정보가 누락되면 DB의 대기 중인 요청을 확인해, 남은 대기 시간에 따라 정보를 복구하거나 요청을 만료시키도록 구현했습니다. 로컬에서 Valkey 재시작으로 대기 정보를 유실시킨 뒤 요청 205건이 모두 남은 대기 시간에 맞게 복구 또는 만료 처리됨을 확인했습니다.
